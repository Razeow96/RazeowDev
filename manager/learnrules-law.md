# Learnrules law — the rule inbox

Type: Law · how a confirmed rule travels from Raze's word to its home, in every repo; pulled through rulesindex when a rule is confirmed, promoted or swept. Update: one rule = one line; replace the line and delete the superseded one in the same edit. The reasoning and the incident behind each rule: `rsot/knowledge/governance-law-rationale.md` §learnrules-law, same rule IDs, open when a rule's judgment is in play.

- **MGR-9** Each repo has one inbox, `learnrulesinbox.md` (State type): only rules confirmed but not yet in their home (FILE-4).
- **LRN-1** A row lands the moment Raze confirms a rule, and the rule is written into its home file in the same step — never deferred to /close or /closeceo, which only sweep for misses.
- **LRN-2** Once the home verifiably holds the rule, its row is deleted in the same edit.
- **LRN-3** Rows carry no number, the file carries no `next:` counter, and a row is date · rule · home · suggest.
- **LRN-4** The inbox is safe at 3 rows or fewer and alarms at ~1k characters of unhomed rules; an alarm is an audit finding for overdue homing, never a split.
- **LRN-5** A rule is written general enough to prevent the class of mistake, never narrowed to the one incident.
- **MGR-11** A binding invariant goes to the repo's rule file in `rsot/rules/`, a lesson to the inbox until its home holds it, and a decision with trade-offs to the module's `sot/` (project-wide: `msot/`) with the Linear issue linking it (LIN-16) — never all three, and never Linear as the home.
- **LEAD-13** Promotion is a move, never a copy: the CEO seat rules the flagged row the moment it is confirmed, assigns its ID in the HQ rule file and deletes the local row in the same pass (FILE-4).
- **LRN-6** The sweep (/close, /closeceo, /auditceo) reads every open row, verifies its home holds the rule and deletes the row; a row whose home is missing is homed on the spot or put to Raze, never left for the next sweep.
