# Dev team — Architect topology (ARCH §5)

Type: Law · topology rules for `architect.md`, pulled through rulesindex when the design places workloads, data or CI. Update: one rule = one line; replace the line and delete the superseded one in the same edit. The reasoning and the incident behind each rule: `rsot/knowledge/architect-topology-rule-rationale.md`, same rule IDs, open when a rule's judgment is in play.

- **ARCH-22** Never plan everything onto one backend: small self-contained features ride serverless or edge, automation and scheduled sync ride workflow runners, static and media ride a CDN, and only genuinely heavy, stateful, core logic earns a place on the backend, split by weight and never by convenience, so a light platform never carries core business logic and the backend never carries what the edge could (ARCH-12).
- **ARCH-12** Infrastructure is designed and drawn (where each component runs, what survives host loss, how components connect), the runtime is verified to do the job before the architecture commits to it, and business logic never lives on a light or low-code platform.
- **ARCH-23** Before designing infrastructure, ask in order: does it already exist as open source (global card §3), can the data or feature be had through an API instead of built, then derive the topology from the audience (global users → CDN for static and media, edge for latency; load balancing and replicas only at a ladder trigger, ARCH-24) and pick the database stack for the workload, never by habit.
- **ARCH-32** Every dataset is classified by workload and placed in its class (transactional, read/UI-serving, high-volume append, cache/session, blob/media, analytics), never one store for everything, with unbounded append growth never sharing capacity with the system's truth, blob and media never in the database, and every placement declaring its growth rate, criticality and scale-ladder trigger (ARCH-24); class shape and lifecycle are the DB seat's (DB-16/17).
- **ARCH-24** Every infra design carries a scale ladder: the today-size version is built now, the upgrade path is written with numeric triggers (users, rps, GB), and nothing on the ladder is built until its trigger fires (global card §3).
- **ARCH-34** Every repo's CI/CD pipeline is designed and stated in the spec when the repo is designed, naming what runs on every push (typecheck · build · lint · mock tests, never a real secret), what gates a merge (a red check blocks), what deploys where from which branch or tag to which environment (OPS-17) and what stays manual and owner-gated (global card §3), with live-dependency smoke tests as their own gated job, the pipeline kept as code in `.github/workflows/` and reviewed like code, and devops provisioning and maintaining it (OPS §2).
- **ARCH-25** Cost posture is read, never hardcoded: the free-vs-quality bias comes from the global card's current posture plus the repo's operator card (status · money path).
