# Drawing law · CI/CD pipeline

Type: Law · the CI/CD pipeline: how it is drawn, in every repo · pulled through rulesindex when drawing a pipeline, briefing devops to build one, or placing a gate (deploy, approval, go-live), together with index-and-legend.md. Update: one rule = one line; replace the line, never add beside it; IDs are append-only. Written 2026-10-28 from the two drawn pages: AYE-M1 World Robot Fight page 6.1 and RS2-M4 page 8.0 (approved 2026-10-25).

Answers: how one change travels from a push to live and back again, which gate can stop it, who taps, and what every step leaves behind. Sits on its own page, one per project, named `<n> · CI/CD pipeline — <project>`; a project with a progress notice (one message per change) draws it as section `<n>.2` of the same page. Seats: the architect draws it; devops builds and runs it (OPS-40) and never draws a gate the page does not hold; tester 2's suite and the security table are its gates; QA reads it. Altitude: step of the pipeline (DRAW-28). Every gate lives here and only here: never on a decision table (DRAW-54), never on an end-to-end lane (DRAW-55).

- **DRAW-56 CI/CD pipeline.** One lane, left to right, in this step order, a step dropped only with its reason written on the page: source (the push, the branch rule (one branch, main; devops knowledge file §1), who may push) → CI (what runs on every push and where; the banner says `CI holds no secrets`) → gate diamond → build once (the same artifact travels to the end, never rebuilt) → staging or preview → stage-2 gates (tester 2's contract and end-to-end suite, REL-22; the security table rows, SEC-52) → approval diamond (`owner: ready to deploy?` with its wait box and its timeout where one exists) → deploy (the script, the machine it runs from, the env it reads; the database step `migrations append-only`, DB-27; the service or VPS step `same version`) → smoke (the release suite against the live surfaces, REL-22) → gate diamond → rollback box (code: the previous pinned version; database: forward-fix only, never reversed; OPS-43) wired back to the smoke step as `re-check` → runtime (the cron, worker or service that now runs it, with its lock) → the consumers that read it (purple ports, DRAW-20). One box = one step; a step running two checks is two boxes side by side feeding one diamond. Every diamond is a gate with both edges labelled: `yes`, and `no · <what blocks> · <the failing check's name> · blast radius <single | site | run>`. Every step box carries, in this order, its seat (who runs it), what it runs, and what it leaves behind (deploy tag · Changelog row · deployment id · message), and the platform it runs on is a purple box under it joined by `runs on` / `applied to` / `pulled into`; a step with no seat, no platform or no leave-behind is red, and the red steps are the build list. Each step's last line reads `not built` or `built, not live` until it is observed running, when it turns green (DRAW-20, DRAW-22); dashed border = planned, solid = runs today, stated in the banner. Never drawn here: a test case (the three test pages), a server topology (infrastructure kind), a provider's product list, or more than one lane per project.
- **DRAW-57 The page agrees with law and the tables.** The gates drawn are the gates the rules own and no other: CI runs devops' mechanical steps (typecheck, secret scan, the clone detector, the code index check) and tester 2's scripts as its test steps; the pre-deploy gate is tester 2's suite, the Security tab's rows and QA's go read from the QA tab; the smoke is the same suite after deploy; approval is the owner's tap, with the timeout the project rules name. A gate carrying a threshold the law retired (a coverage percentage, QA re-running a suite, a per-feature contract test in CI) is a defect on the page, fixed before the page is approved. The expected result of every gate is a row of the project Sheet's QA tab or Security tab (QA-27, SEC-46), and the diamond names that row; a gate with no row, or a row with no gate, is red. Today's PASS or FAIL on a gate comes from the run of record (the CI run, the release suite log, OPS-41's `gh run` result), never by hand.
