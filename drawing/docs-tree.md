# Drawing law · Docs & files system tree

Type: Law · docs & files system tree: how it is drawn, in every repo · pulled through rulesindex when drawing one, together with index-and-legend.md. Update: one rule = one line; replace the line, never add beside it; IDs are append-only.

Answers: on the org-structure standard board, which documents exist, what each AI turn loads and pulls, in what order, and each type's cap; on a project board, which files the system being built is made of and what loads or runs each. Drawn on its own page, not as a module section. Seat: architect, `/architecture-ddd-draw`. Standard: the org-structure board and its text copy `HQ-M1-org-structure/sot/doc-tree.md`.

- **DRAW-38 Docs & files system tree.** One kind at two altitudes. On the org-structure standard board it maps the org's documents: what exists, what each AI turn loads and pulls, each type's cap. On a project board it maps the files of the system being built, never the repo's documentation: config (file shape), scripts (process shape, each named with its file and language), data (cylinder: stores and served files), instruction files a turn or command loads, and the documents of the design (the contract and the written copy in msot and sot). Shapes encode the type (rounded = Law or Card · document = Index or design document · stacked documents = Knowledge, Skill, Template, instruction · process = script · cylinder = Data or State · file = Config · chevron = trigger); colour encodes the state (green = exists and loads or runs · blue = not written yet · yellow = pulled by request · purple = outside · white = decision). Each node carries name and path · type and what loads or runs it · size today, measured from the file once it exists, against its cap where one applies (owner ruling 2026-10-22).
- **DRAW-46 Pages.** On the org-structure standard board, one page each: doc types · layer flow · folder structure · size caps · load per seat type · state and change list. On a project board, one page only, named `<n> · Docs & files system tree — <name>`: at the top the files table (one row per file: path · type · what loads or runs it · state · size), below it the tree drawing with the load and write arrows. A folder or step is a black-outlined white box, never a doc fill (owner ruling 2026-10-22).
- **DRAW-47 Moves with the docs.** Any doc added, moved or renamed updates the docs tree in the same change (figma-law DRAW-7).
