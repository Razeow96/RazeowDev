# Drawing law · Functional & non-functional flow

Type: Law · functional & non-functional flow: how it is drawn, in every repo · pulled through rulesindex when drawing a functional & non-functional flow, together with index-and-legend.md. Update: one rule = one line; replace the line, never add beside it; IDs are append-only.

Answers: how each feature of a module works, and how well. Sits as sections on the module's page (FIG-2). Seat: architect, `/architecture-ddd-draw`. Altitude: feature step (DRAW-28). Flow and cards are hand-built inside the feature's section (figma-law DRAW-2: a native flowchart cannot live in a section); the measured shape to copy is `rsot/knowledge/figma-drawing-recipes.md` (DRAW-49).

- **DRAW-8 Layout.** One section per feature on the module's page, one drawing per feature: the functional flow (how it works) on top, its non-functional cards (how well) under it. The section shows only the module's own steps; anything entering or leaving is ONE purple port box named with the other module's full code and the event (`→ <code> <feature> · <Event> vN` or `← <code> · <Event> vN`), and that code is the link to its page. No cross-module arrow inside a module page.
- **DRAW-9 Feature numbering.** Features carry the module's item codes `<code>.<k>`, top → down, and cards carry `<code>.<k>.<j>`, so an edge or a card reads unambiguously.
- **DRAW-11 Shapes.** Step = rectangle · decision = diamond · store = cylinder · port or outside system = purple box · guarantee = card. Colour only from DRAW-20. A decision's out-edges are labelled with the answer (yes · no: <named error>).
- **DRAW-34 Non-functional cards.** They sit directly under each feature's flow, in the same section: one card per real guarantee, a title over a two-column table with nine rows — where (the module table, no schema names) · platform · tech · source of truth · number · detected by · fails safe · expected result (the metric a test asserts: a count, an exact value, a status, a time or a cost, never a described outcome) · proved by (stage 1 case run by tester 1 · stage 2 contract check · AI walk on staging · stage 2 security). Never a separate guardrails page. A card whose expected result cannot be measured goes back to the architect before the page is approved (owner rulings 2026-10-19, 2026-10-28).
- **DRAW-12 Blast radius.** Every reject, drop or error edge carries its blast radius — `single`, `scoped (<scope>)` or `global` (ARCH-42).
- **DRAW-13 Adapters are drawn, not hidden.** Where sources differ per platform: `platform adapters → normalize → one common typed record` (backend knowledge file §1), with the place the unifying field is stamped.
