# Drawing law · End to end test script

Type: Law · the end to end test script: how it is drawn, in every repo · pulled through rulesindex when drawing a journey test or briefing the release tester's journeys, together with index-and-legend.md. Update: one rule = one line; replace the line, never add beside it; IDs are append-only. Owner ruling 2026-10-23: one lane per path the board draws, from the first module to the last outside service; the example mapping board was dropped.

Answers: for every path a record can take through the whole pipeline, which stage it reaches, what each stage must leave behind, and what proved it. Sits on its own page, one per project, named `<n> · End to end test script` (owner ruling 2026-10-26). Seats: architect draws it; the release tester runs it against the live surfaces (REL-21) and writes the result on the lane. Altitude: stage (DRAW-28).

- **DRAW-55 End to end test script.** The lanes are the rows of the release tester's scenario table (journey id · scenario · use case · runs · expected result per stage, REL-20), which the owner reviews and approves before the suite runs, a deliberately broken alarm being a row of its own (owner ruling 2026-10-28); one lane per path or class the board draws (never per campaign or niche), named by its journey id (`J-<letter>`) and the path in plain words; in the lane, one box per stage in flow order, each carrying the surface read (`table.column`, a file address, a provider state) and the expected value at that stage, in that order, so the lane reads as the check list the suite runs; one test identity per lane, pushed in dry-run or on a test record inside the cost ceiling named in the section banner, never reaching a real person or inbox; a stage that has no dry-run is drawn with a dashed border and the banner says it is replayed from the newest real record (read-only), so a green lane is never mistaken for a live send; today's result (PASS / FAIL per stage and the date) comes from the release suite's run of record, never by hand; a stage with no surface or no expected value is red, and the red stages are the build list. Gates are not drawn here (CI/CD pipeline page); escapes the lanes missed are logged in the project Sheet's Escape log by the team lead, devops or tester 1 (SHEET-2), then added as a stage check only when no lower layer can see them (REL-15).
